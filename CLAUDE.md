# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`pano-boilerplate-plugin` is the **committed output of `pano-plugin new`** (`@panomc/plugin-kit`): the id is
`pano-plugin-boilerplate`, the Kotlin package `com.panomc.plugins.boilerplate`. Do not hand-edit it to add features.
The template lives in `theme-core/packages/plugin-kit/bin/templates/plugin/`; change it there and regenerate:

```bash
cd <pano>/plugins && bunx @panomc/plugin-kit new pano-plugin-boilerplate --package com.panomc.plugins.boilerplate
```

(`--local <theme-core dir>` links a local checkout instead of the published kit.) The output needs no hand edit: the
template already carries the two imports in `build.gradle.kts`, the explicit `getValidationHandler` in `GetHelloAPI.kt`
and `apiLevel=1` in `gradle.properties` (the pinned Pano dependency has no API level yet; delete that line once it has).
`MEASURE.md` is the record of how that was measured.
Kept on top of the generated output in this repo only: `agent-guide/`, `design/`, the agent files and the last
paragraph of `README.md` (a scaffolded plugin does not get them yet).

A Pano plugin is a **PF4J plugin**: a Kotlin backend (extends `PanoPlugin`, adds `@Endpoint` / `@Dao` / `@EventListener`
beans) plus a Svelte UI. The site UI is a set of named views: one `.svelte` file per view under `src/theme/views/`, with
`export const view = { path: '/x' }` in it and no registration code. The view id is `<ns>:<Name>`
(`boilerplate:HelloPage`: the plugin id without `pano-plugin-`, then the file name) with a contract version; a theme can
redraw it. Endpoints declare relative paths (`/hello`) and are served at `/api/plugins/pano-plugin-boilerplate/...`
(panel endpoints at `/api/plugins/pano-plugin-boilerplate/panel/...`). The rules are in `agent-guide/`. The authoritative explanation of the plugin system
lives in **`../pano-web-platform/CLAUDE.md`**.

## Commands

```bash
bun install                      # installs @panomc/plugin-kit and @panomc/sdk (file: links to ../theme-core while unpublished)
bun run dev                      # pano-plugin dev: builds the jar once with -Pnoui, then rollup watch
bun run build                    # pano-plugin build: the UI package only
bun run check                    # pano-plugin check: view, import, lock and style rules
./gradlew build                  # Kotlin + UI -> build/libs/pano-plugin-boilerplate-local-build.jar, copied to panoPluginsDir
./gradlew build -Pnoui           # backend only
```

Gradle needs `PANO_SDK_DIR=<umbrella>/theme-core/packages/sdk` while the SDK is unpublished.

## Conventions

- Premium plugins use the RS256-JWT license system (`PluginLicenseClient` / `verifyLicense()`).
- `pano-plugin.lock.json` is generated by the build; commit it.
- Releases (incl. publishing to the Pano resource store via `semantic-release-pano`) run on `dev` (prerelease) and
  `main` (see `.releaserc.json`): one-line **conventional commit** messages, never a hand-bumped version.
- JavaScript with JSDoc only in the UI; no TypeScript.

## Agent guide

You are in a **Pano plugin template** (what a new plugin is started from). Whatever you write here is copied into other plugins, so it must follow the guide exactly.

Read `agent-guide/README.md` first, then **only** the topic file it points to for your task. Decide from the
request and the code; ask only where the guide says a wrong guess is costly. `agent-guide/` is a synced copy: edit it
in `theme-core/agent-guide/` (repo `PanoMC/sdk`) and run `bun scripts/sync-agent-guide.js` there.

The three rules you will break first:

1. Every site view is a named view `<ns>:<ViewName>` with a contract version: one `.svelte` file with `export const view = {...}`, never a registration with `component` (`plugin-views.md`).
2. Declare relative API paths only; Pano serves them at `/api/plugins/<pluginId>/...` and `/api/plugins/<pluginId>/panel/...`. Lists answer `{ items }` (+ `{ page }` when paged), errors `{ error: { code } }` (`plugin-api.md`).
3. Do not add features by hand to generated output: `pano-boilerplate-plugin` is what `pano-plugin new` writes, its template is `theme-core/packages/plugin-kit/bin/templates/plugin/` (`plugin-new.md`).
